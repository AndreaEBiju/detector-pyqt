# M1 signal-viewer spike — results

## Purpose

Validate that pyqtgraph + h5py lazy loading can deliver responsive
pan / zoom on a 2-hour multi-channel recording, before committing to
the M2+ migration build.

## How to reproduce

```bash
cd /Volumes/PortableSSD/detector-pyqt
pip install -e ".[dev]"   # once
python scripts/m1_benchmark.py --recording <path/to/2h.mat>
```

The benchmark times 20 random pans at three viewport sizes per the
plan's M1.3 targets and writes the AUTO section below. Run multiple
times against different recordings; results from each run replace
the AUTO block (prose around it is preserved).

For interactive feel — what the benchmark can't measure — drive the
GUI directly:

```bash
python ui/app.py <path/to/2h.mat>
```

Scroll-wheel zoom, drag-pan, pinch on macOS — see whether it feels
responsive in the seat, not just on paper.

## Pass bars (plan M1.3)

| Viewport | Target | Rationale |
|---|---|---|
| 60s   | < 100 ms  | perceptually instant, single pan keystroke |
| 600s  | < 300 ms  | still feels fast for medium-zoom navigation |

Peak RSS target: **< 2 GB** for a 2h recording (8.6 GB raw float32 →
lazy loading keeps memory bounded).

## Preliminary results — local 22-min recording (no Qt, read-only)

Before the full Qt benchmark on the 2-hour Drive recording, we tested
just the `LazyRecording.get_range()` read path on the local 22-min
file `M10E10_ORE_CME_stim_rec_1908_notched.mat`. Two scenarios:

**Scenario A — raw MATLAB `_notched.mat` `(n_ch, N)` layout (the
existing on-disk format):**

| Viewport | mean read (ms) | target (ms) | verdict |
|---------:|---------------:|------------:|:--------|
|     60s  |   ~700         |   100       | ❌ fail |
|    600s  |  ~4 800        |   300       | ❌ fail |
|   1200s  | ~11 400        |   —         | unusable |

Cause: `(n_ch, N)` row-major HDF5 means each 60s viewport read is 5
non-contiguous slices, one per channel. Disk seeks dominate.

**Scenario B — after one-time ingest to flat `(N, n_ch)` HDF5 with
chunked storage along time (`scripts/m1_ingest.py`):**

| Viewport | mean read (ms) | target (ms) | verdict |
|---------:|---------------:|------------:|:--------|
|     60s  |   ~96          |   100       | ✅ pass (just) |
|    600s  |   ~800         |   300       | ❌ fail |
|   1200s  |  ~1 800        |   —         | (extrapolates to ~7000ms for 7200s) |

The 28× speedup at 60s closes the small-viewport gap but the wide-
viewport reads are still bound by raw bandwidth — 14M samples take
~800ms to read from disk regardless of layout. That confirms the
plan's M1.4 mitigation is needed for wide-zoom scenarios:
**pre-computed downsampled overview file** for viewports beyond ~2 min.

Ingest cost on this hardware: 22-min file → 26s conversion, output
505 MB. Extrapolates linearly to ~150s for a 2-hour file.

## Decision

After running the benchmarks AND driving the GUI:

- [ ] Proceed to M2 (browser + labeling) — unconditional
- [x] **Conditional GO: proceed to M2 with M1.4 mitigation #1
      (pre-downsampled overview file) as the first M2 task**
- [ ] Abort migration

### Rationale

- ✅ **Architecture validated.** pyqtgraph + h5py lazy reads work;
  signal renders correctly; mouse pan/zoom refetches; memory bounded
  (1.3 GB on 20-min file). All M1 acceptance criteria except
  performance bars met.
- ⚠️ **60s viewport: 121 ms** — over the 100 ms target by ~21 ms, but
  perceptually fine per user testing. Below the ~150 ms human-
  perception threshold for "instant".
- ❌ **600s viewport: 865 ms** — clearly over the 300 ms bar. This
  is the disk-bandwidth ceiling: reading 14M float32 samples for a
  600s view is ~50 MB of I/O regardless of HDF5 layout. The plan's
  M1.4 mitigation #1 (pre-downsampled overview) is the right
  solution: at the wide viewports the human eye can't resolve more
  than ~5000 points anyway, so the overview file stores exactly that.
- ⚠️ **7200s untestable on the 20-min Drive recording.** Read-only
  extrapolation from the 22-min local file suggested ~7 s for raw
  flat-HDF5 reads at 7200s; the overview fallback will bring this
  to ~10 ms.
- 📍 **Recording-duration scope.** User has 2h files but tested on
  20-min. The 2h benchmark is a useful confirmation but isn't
  required to lock the architecture in — the failure mode at wide
  viewports is bandwidth-bound and well understood. If subsequent
  2h testing flags new issues, escalate from M2.

### What carries forward into M2

- `ui/widgets/signal_viewer.py` — `LazyRecording` + `MultiChannelViewer`
  including the post-fix sigRangeChanged hook + `setLimits` bounds.
- `ui/app.py` — toolbar with Reset / Fit all actions.
- `scripts/m1_ingest.py` — flat-HDF5 ingest converter (per-recording
  one-time cost). M2 will likely wrap this in an auto-ingest-on-open
  flow so the user never thinks about it.
- `scripts/m1_benchmark.py` — becomes the perf-regression test for
  every future signal-viewer change.

### M2 task ordering

Per the conditional-GO decision, M2 starts with:

**M2.0 — Pre-downsampled overview file (M1.4 mitigation #1).**
At ingest time, also compute a coarse `(N_overview, n_ch)` array
where N_overview ≈ 5000–10000 samples regardless of recording
length. Store as `/y_overview` in the same flat HDF5. The viewer
switches to the overview dataset when the viewport spans more than
~120 s (point density per pixel doesn't warrant the full data).
At narrower viewports, keep using `/y`.

Acceptance criteria for M2.0:
- Wide-viewport (600s+) pan/zoom < 300 ms on the 20-min file.
- Bit-identical render at narrow viewports (we still read `/y`
  directly when zoomed in).
- Ingest cost still ≤ 1.5× the current m1_ingest runtime.

After M2.0, the rest of M2 proceeds as planned in
`pyqt_migration_plan.md` (browser + labeling).

### Mitigation options considered (plan M1.4)

| # | Option | Status |
|---|---|---|
| 1 | Pre-computed downsampled overview at ingest | **chosen** as M2.0 |
| 2 | PyQtGraph OpenGL backend (`useOpenGL=True`) | not needed for now — bottleneck is disk read, not GPU paint |
| 3 | Abort and revisit later | rejected — architecture works; wide-viewport issue has a clean fix |
